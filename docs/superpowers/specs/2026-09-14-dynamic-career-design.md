# 动态实习与职业研究设计

已依据用户 9 月 12 日、9 月 14 日的「按建议执行」批准实施。主体为现有 Next.js 项目，保留另一项目不变。

## 首个交付单元

打通自由专业输入、岗位能力匹配、云端目录刷新、联网研究、行业/晋升/竞争力建议。已有地图、职业百科、证书页面保留；不以地图作为主要入口。

## 数据真实性

企业研究对象、职业方向、招聘平台搜索入口、已核验在招职位是四种不同数据。旧企业库中的常见岗位不得称为当前招聘。榜单年份沿用原来源，不升级年份。没有职位证据时不展示「在招数量」；英语六级是个人提升目标，只有具体招聘公告要求时才标记为硬门槛。

造纸、传统书刊印刷、数字印刷、设计、设备/工艺分别有职业分析。晋升路径为一般方向建议而非承诺。机器数量不能直接推导机长数量；必须知道机型、班次、编制、储备培训和空缺。现任员工年龄、退休等待、往届录用学校与录用率没有公开依据则显示未公开，不推测个人信息。

## 架构

- Next.js 从静态导出迁移为服务器运行，默认部署到支持 Node.js 的平台。旧 GitHub Pages 版本不受本地改造影响，新功能不能使用旧静态发布脚本。
- `lib/career`：独立专业画像、目录校验、企业/职位匹配、有效期、学习差距与晋升情景计算。
- `data/career-catalog.json`：有来源的基础职业目录，属于离线备份，不伪装实时。
- `/api/catalog`：读取 Supabase 最新公开目录，失败明确返回备份状态。刷新强制重新请求；所有共用页面调用同一动态数据层。
- `/api/research`：仅搜索允许的公开来源，不自动抓招聘平台，不把搜索摘要升级为职位。支持实习、行业晋升、竞争/考研三个主题。专业/企业文本会发给检索服务；不发送简历、姓名或联系方式。
- Firecrawl REST 查询只在用户主动点击或受保护后台任务调用。同一查询缓存 24 小时；线上新查询需要登录和数据库原子额度检查。开发环境可显式开启本机测试，仍有进程总预算；不作为线上限流。
- Supabase 用 `auth.uid()` 隔离档案。停用同步码即身份的旧方案。游客可浏览、可选择本地保存；云同步需要账号授权。
- 后台更新工具支持校验后导入完整目录，定时任务更新管理员选定研究主题；不会在未配置凭据时宣称已开启同步。

## 界面

首页为专业/年级/城市/已有技能表单，联动企业、职业、技能差距、证书、阶段计划、简版城市分布。独立研究区域展示带链接的检索线索、获取日期、来源可信层级和缓存状态。职业晋升面板列出技术与管理双路径、需要核实的问题，并提供明确标注为假设的编制情景计算。

## 验证

自动测试覆盖空输入、未知专业、跨行业匹配、不同专业不同结果、过期职位、恶意 URL、目录格式错误、缺失晋升数据、成本限制。构建与新增代码 lint 通过。浏览器检查桌面/手机、专业切换、目录刷新、真实检索结果、失败状态和过期不显示在招。数据库隔离策略提供 SQL 校验步骤；未连接数据库时不能报告远端隔离已经验证。

## 配置边界

本地代码实施不等于已发布到网上。Supabase 迁移、服务器部署、线上检索密钥和定时任务只有用户选择的实际环境接通后才算开启。可在本机验证真实 Firecrawl 调用；不读取或传播旧凭据文件，不使用既有发布脚本推送。
