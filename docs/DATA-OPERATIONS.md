# 数据怎样持续更新

## 三层数据，不能混为一谈

1. 企业目录：官网、行业/能力标签、历史资料。用于发现研究对象，不承诺在招。
2. 联网线索：用户点击研究或受保护定时任务检索政府、学校、公共人才平台及已登记企业官网。返回链接和摘要；记录检索时间而非公告发布时间，缓存24小时，避免同一查询反复付费。
3. 已核验职位：维护者打开原始公告，确认岗位、企业、城市、真实要求、核验时间和有效期，才录入职位。当前种子没有有效职位；搜索摘要不自动升级成招聘事实。

这比每位访客每次刷新都调用AI便宜、可追溯。不是全网全量实时招聘数据库，不能保证任意专业都准确覆盖；专业映射和企业标签需要逐步维护扩充。招聘平台目前提供搜索入口，不冒充已授权API或公司专属职位链接，不绕过登录/验证码或采集个人简历。

## 云端初始化（本任务没有替你执行）

- 建立Supabase项目，在SQL编辑器执行 supabase/schema.sql。先备份旧数据库；脚本保留旧 user_data 行，但撤销原版匿名同步码访问。旧公开网站的同步码功能会因此失效，先安排迁移与旧站停用，不能直接在仍需运行的旧库执行。
- Auth开启邮箱账号，配置网站URL/回调及邮箱验证；建议设置验证码和账号注册限流。本站不使用匿名账号执行付费检索。
- 浏览器配置 NEXT_PUBLIC_SUPABASE_URL 和 NEXT_PUBLIC_SUPABASE_ANON_KEY；服务器另配 SUPABASE_SERVICE_ROLE_KEY、FIRECRAWL_API_KEY。服务密钥不能带 NEXT_PUBLIC_ 前缀，不能上传Git或发给访客。
- CRON_SECRET 设置为至少32字符的随机秘密，用于更新入口。ALLOW_LOCAL_RESEARCH 不用于线上。
- 先在本地执行 node scripts/publish-catalog.cjs 仅校验。确认后你可执行 node scripts/publish-catalog.cjs --publish，把基础70个研究对象发布到新库。
- 用两个不同账号实测：A不能读写B的 career_profiles；匿名不能访问私有资料、额度表或调用额度RPC。服务密钥只能在服务器使用。本地测试不能证明线上RLS已正确执行。

## 更新企业与职位，不重新发布前端

修改或准备完整的 CareerCatalog JSON：version=1、updated 日期、employers、vacancies、majors、roles。字段示例见 data/career-catalog.json 及 lib/career/types.ts。

企业 evidence 标记 enterprise/historical/lead，来源未知不要填假地址，核验未知用null。历史印刷排名只是原版2025参考，不当成今年榜单或招聘竞争力。

职位至少包含 id、employerId、title、tags、city、requirements、sourceUrl、checkedAt、expiresAt、status。status=verified 只供已核验记录，日期必须真实；页面还会隐藏关闭、过期、未来核验或超过30天未复核的记录。CET-6只在招聘公告写明时加入岗位 requirements，不能把个人目标变成所有公司硬要求。

```powershell
node scripts/publish-catalog.cjs path/to/catalog.json
node scripts/publish-catalog.cjs path/to/catalog.json --publish
```

第二条会覆盖 main 快照，先保留你上次发布的JSON；回滚可重新发布旧快照。工具不会改私有档案，也不会根据AI摘要自动加职位。

## 定时更新（入口已实现，定时器尚未配置）

让你选择的托管平台/任务服务每天一次发送 POST /api/refresh/，请求头 Authorization: Bearer 后跟服务器 CRON_SECRET。不要把秘密放在URL或网页里。入口不接受访客传入的任意专业列表，只读取服务器 CAREER_REFRESH_MAJORS，最多三个专业，默认印刷工程、制浆造纸、包装工程。

它刷新实习研究缓存，不自动修改已核验职位库。相同查询24小时内复用；全站每天50次、单账号每天5次，按上海日期重置。定时任务只占全站额度。数据库额度不可用时停止付费调用，缓存写入失败会告警。没有配置持久缓存/额度时，线上联网研究不会降级为无保护调用。

一次搜索最多5条网页结果，服务可能消耗多个积分；次数配额不是人民币预算，也不能限制密钥被别处使用。另在检索服务后台设置积分/费用限制，观察实际用量后再调整额度SQL。缓存命中不重新检索；“查到时间”不是岗位“发布时间”。

## 深度调研怎么录入

- 工作环境：传统印刷、数字印刷、造纸等目前是通用专业介绍，问清倒班、设备、安全培训、噪声/粉尘/化学品和现场条件。不要把行业标签直接套成具体厂的结论。
- 晋升：从年报/公开设备资料或企业访谈获取生产线、机器、班次、机长编制、培训/内部竞聘、离职及扩产计划。只有机器数也不能推出晋升年限，更不能计算员工退休时间。页面编制工具明确是情景估算，不是预测。
- 竞争者：企业官方校招对象/要求、学校培养方案只能证明招聘范围或课程，不能推断往届真实录用学校占比。仅使用公开、授权、去个人化统计；目前页面不提供不存在的数据。
- 考研：核对当年招生目录、专业与研究方向、考试科目和培养安排；不把西安理工与武汉理工/武汉大学等学校混为一谈。

建议后续加企业调研记录/证据编辑后台。本次先交付可靠检索与推荐流程，而非无法核实的“行业全知”评分。
